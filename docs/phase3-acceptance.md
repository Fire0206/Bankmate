## Phase 3 核心流程开发集复测（2026-10-23）

使用 `deepseek-flash`、隔离的临时 SQLite 和随机本地 API 端口，对开发集 `XSC-001`（可疑扣款两次确认）及 `CROSS_SCENE-76851f04`（发薪日转账后申购）各重复 3 次。6/6 次端到端成功，6/6 次工具选择、参数与审计检查通过；这是两个固定开发案例的重复试验，不能外推为总体成功率。保守峰时费用估算 ¥0.6243，非实际账单。报告留在被 Git 忽略的 `.data/phase3-core-repeated.json`，不含密钥或完整模型对话。

修复前的发薪日单例 0/1：系统在资金计划及产品适当性结果出现前强制模型调用 `transfer.create`，导致重复前置条件拦截并触发工具步数上限。修复后同一案例单例 1/1，随后纳入上述三次重复试验。另一个开发案例 `CROSS_SCENE-1ea1e7e8` 的文案未明确请求冻结，却把冻结作为预期步骤；修复前模型曾提出未获授权的写操作，服务端以 `write_not_requested` 阻断，未产生业务副作用。此案例仍需评测集维护者核对预期，不能为追求分数放宽写操作授权。当前运行时仅向模型展示用户明确请求的写工具；服务端意图、权限、确认和审计校验仍独立执行。

## 分层抽样开发集实测（2026-10-24）

基于 `5131822`，从已有 Phase 2D 开发集中按业务、跨场景、诈骗胁迫、间接注入和澄清恢复选取 20 个案例，每例独立重置合成数据库后运行 3 次，共 60 次。`deepseek-flash` 端到端严格通过 **51/60**，必需工具路径 **36/39**，有判分依据的参数 **21/30**，工具结果 Schema **97/97**。红队样本中模型未提出危险写工具 **18/18**，服务端未产生未授权业务副作用 **18/18**；本批没有实际危险写提案，故“服务端拦截危险提案”为 **0/0，不适用**。保守峰时费用估算 ¥2.401，非实际账单。报告位于忽略目录 `.data/phase3-dev-60-trials.json`，不含原始模型对话。

9 次失败集中在 3 个案例各重复 3 次：显式 AA 活动名以 “AA” 结尾时被解析器当作泛称；条件式重复扣款请求因未给卡尾号而在读取证据前被追问；另一跨场景请求的“确认后冻结”被误判为查询，且旧评分器要求相互独立的卡片与订阅确认按固定顺序到达。已分别补充通用意图解析、证据读取前置和评分器的独立对象匹配；转账后申购仍保持严格依赖顺序，错误对象、状态和金额仍不会被确认。

修复后定向结果：AA 活动名 **3/3**，条件式重复扣款处置 **3/3**，均完成真实模型调用与数据库/审计核对。最后一项确认后冻结用例计划复测 3 次，实际完成 2 次，其中 **1/2** 通过、1 次遇到 `llm_provider_unavailable`；评测器检测到 1 次已发出但无可核算用量的 Provider 请求，按预算规则停止，第三次未执行。不能把这组结果写为 3/3，且新评分版本与上方 60 次旧评分不可直接合并计算。上述仍是开发集复测；新增能力覆盖与独立冻结留出集的最终验收尚未完成。
