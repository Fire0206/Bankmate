# 开源许可与贡献权属

## 计划许可证

项目拟使用根目录 [`LICENSE`](../../LICENSE) 中的 Apache License 2.0。Apache-2.0 允许在满足其条件时使用、复制、修改、再许可和分发作品，包括商业使用；再分发时须提供许可证副本、标明修改并保留适用的版权/专利/商标/归属通知。若上游发行包含 `NOTICE`，派生分发须保留适用归属信息。当前尚无已确认版权主体或 `NOTICE` 文件；不虚构持有人，也不因依赖尚未评估而提前建立空 `NOTICE`。

Apache-2.0 的专利授权由每位贡献者针对其贡献授予，范围限于其可授权且被贡献本身或与作品组合所必然侵犯的专利主张；对作品/贡献提起专利侵权诉讼时，相关专利授权按许可证条款终止。许可证第 5 节规定，贡献者有意提交纳入作品的贡献按 Apache-2.0 条款处理，除非另有单独协议；贡献者需确认自己有权作此提交。

以上摘要以[官方 Apache License 2.0 正文](https://www.apache.org/licenses/LICENSE-2.0.txt)为准，不构成法律意见。许可证文件准备不表示团队已确认代码权属或授权仓库公开。每位比赛团队成员在仓库公开和贡献代码前，必须确认个人、学校、雇主、合作方和赛事相关的权利与限制；团队负责人需确认谁有权授予许可证。

## 贡献与第三方组件

- 当前不要求 CLA；仓库管理员应在接收贡献前确认 `CONTRIBUTING.md` 的许可声明适用于实际权属安排。
- 每项外部代码、复制片段、字体、图标、数据集和模型资产登记来源、版本、许可证、修改情况和分发条件。
- 仅满足许可证兼容性和赛事权属要求的组件可纳入公开发布；需保留上游许可证文本、版权声明和修改声明。
- `NOTICE` 不是无条件必需。只有上游许可/归属要求或团队决定有必要时才添加，并按 Apache-2.0 第 4 节处理上游已有 `NOTICE`。
- 公开发布前由仓库管理员执行 [`public-release-checklist.md`](public-release-checklist.md) 并留存核查记录。

## Phase 0 依赖初筛（2026-10-17）

本轮没有复制或改编第三方源码。对当前锁定并安装的依赖元数据做了初步扫描：前端检查到 199 个包清单，Python 环境检查到 31 个发行包；主流许可证为 MIT、Apache-2.0、BSD、ISC、PSF 和 BlueOak。初筛没有发现 GPL/AGPL 依赖，但这不是完整的法律审查，也不涵盖未来版本。

需在公开前复核的依赖例外：

- `lightningcss`（MPL-2.0）是 Vite/Tailwind 开发构建链的一部分。
- `caniuse-lite`（CC-BY-4.0）是 Browserslist 开发依赖数据。
- Python `colorama` 缺少 SPDX License-Expression 元数据，但发布分类标注为 BSD License；发布前核对其许可证正文。
- `minimatch` 使用 BlueOak-1.0.0；`type-fest` 声明 MIT OR CC0-1.0。

以上为开发工具链依赖；当前应用构建没有把它们作为业务功能或真实服务集成。仓库管理员仍需检查锁文件中的完整传递依赖、实际分发的构建产物和上游 NOTICE/归属要求，判断是否需要随公开发布提供额外许可证/NOTICE 文本。不要仅凭包管理器中的 SPDX 字段认定义务已完成。
