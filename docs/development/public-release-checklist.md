# 比赛提交前仓库公开检查清单

策略：**Private-first, Open-source-on-submission**。本清单准备阶段供团队审阅使用；完成清单不会自动公开仓库。最终公开只由仓库管理员在确认后手动操作。Codex 不得更改仓库可见性。

## 赛事与授权

- [ ] 核对 2026 官方最新提交规则、截止时刻、时区、材料格式和开源要求；保存来源链接、发布日期和核对日期。
- [ ] 确认作品著作权、专利、商标、学校/雇主/合作方权利及比赛主办方的作品使用权条款。
- [ ] 每位正式贡献者确认其提交内容可在 Apache-2.0 下发布；确认第三方或生成内容的权属。
- [ ] 团队负责人/仓库管理员记录公开批准及计划时间；若规则要求保持私密或权属不明，不公开。

## Git 历史与内容

- [ ] 检查全部 Git 历史、分支、标签和 LFS 对象，不只扫描当前工作树。
- [ ] 使用 Secret Scanner 检查 API Key、Token、密码、私钥、`.env` 和 CI 日志；若发现，先撤销凭证，再清理历史并验证。
- [ ] 检查个人信息、真实账户/交易数据、联系方式、团队内部信息、未公开研究/赛事资料和内部文档。
- [ ] 删除临时文件、调试输出、构建缓存和不可公开附件；确认 Artifact 没有敏感信息。
- [ ] 检查 Issue、PR、Projects、讨论和 Action Artifact 的可见性及内容；关闭或清理不适合公开的内部内容。

## 第三方与供应链

- [ ] 核对直接/间接依赖、锁文件、复制代码片段、字体、图标、数据集和模型资产的许可证与再分发条件。
- [ ] 复核 Phase 0 初筛中 `lightningcss`（MPL-2.0）、`caniuse-lite`（CC-BY-4.0）、`colorama`（BSD 分类但缺 SPDX 表达式）、`minimatch`（BlueOak-1.0.0）和 `type-fest`（MIT OR CC0-1.0）是否仍在锁文件中及其分发/归属义务。
- [ ] 对需要归属声明或许可证副本的材料保留版权/License 文本；按 Apache-2.0 第 4 节和上游要求聚合 `NOTICE`。
- [ ] 明确未满足兼容条件的材料已移除或获得书面许可；记录扫描工具和扫描日期。
- [ ] 检查构建脚本、GitHub Actions 和依赖钩子不会上传私有源码、密钥或额外 Artifact。

## 发布设置

- [ ] 确认 LICENSE 中授权主体及团队授权经过审核；Apache-2.0 文本本身不替代版权归属确认。
- [ ] 设置安全漏洞报告渠道和维护者角色，校准公开后的 Issue/PR/Review 设置。
- [ ] 确认公开分支 CI、分支保护、必需状态检查和发布标签无秘密依赖。
- [ ] 管理员在仓库设置中人工将 Private 改为 Public（若团队与官方规则批准），并记录操作者、日期和审批依据。
- [ ] 公开后再次检查匿名访问时的仓库内容、Actions、文档、Artifacts、Issues 与 Releases。
