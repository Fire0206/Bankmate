# 题目与评审要求对照

用户通过 BankMate 网页工作区以自然语言提出银行业务请求，系统通过受控业务工具查询信息、提交操作并反馈服务端执行结果。赛题要求至少覆盖六类核心场景中的三类，并鼓励覆盖全部场景；当前版本覆盖六类场景。

## 赛题功能要求

| 场景           | 已实现能力                                   | 用户可以办理                                                                                                                           |
| -------------- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 智能转账       | 收款人、即时转账、定时转账、AA 分账          | 按姓名、手机号或备注选择收款人；查看转账记录；创建或取消定时转账；发起 AA 分账并查看参与人的收付状态。确认后更新账户余额和交易流水。   |
| 账单分析       | 交易筛选、收支统计、月度与年度账单、异常提示 | 按时间、类别和商户查询流水；查看收支趋势与分类汇总；查看重复扣费等账单核对提醒。                                                       |
| 理财操作       | 产品查询与比较、风险问卷、申购、赎回、持仓   | 查询产品及风险等级；完成风险评估；确认后办理模拟申购或赎回，并查看账户余额、持仓和订单变化。                                           |
| 卡片管理       | 申请、限额与交易设置、冻结、解冻、挂失、补卡 | 查询银行卡；申请新卡；调整消费限额与线上支付设置；办理冻结、解冻、挂失或补卡。操作按风险级别确认。                                     |
| 订阅与代扣管理 | 周期扣费识别、续费提醒、续费状态管理         | 查看订阅项目、扣费金额和续费时间；确认后暂停、恢复或取消自动续费。                                                                     |
| 跨场景联动     | 可疑扣款处置、发薪日规划、生日安排           | 结合账单、订阅和银行卡处理可疑扣款；结合余额、收支和理财产品规划发薪日资金；设置生日预算、预留资金和礼品订单。涉及写入的步骤分别确认。 |

账户、交易和理财产品使用模拟数据；账单提示由可解释的账单规则生成，供用户核对。

## 评审要求对应

### 任务完成率（40%）

- 六类场景均可通过自然语言入口调用对应业务能力；信息不足时，系统会先询问用户补充。
- 跨场景任务按业务依赖执行。可疑扣款任务先读取账单和订阅信息，再提出银行卡或自动续费操作；发薪日任务结合资金和收支信息，规划转账与理财步骤。
- 任务、步骤、待确认操作和执行结果由服务端保存。用户可以查看进度、补充信息、确认或取消操作，并在刷新后恢复任务。
- 余额、交易、账单统计、产品适配和操作状态由服务端业务逻辑计算并返回；页面结果与账户、订单、持仓和交易记录一致。

### 安全合规性（30%）

服务端按绿、黄、红三级判断操作权限；黄色操作需要用户确认，红色操作增加验证码校验：

| 权限级别 | 执行方式                                 | 典型操作                                                                                                                                             |
| -------- | ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 绿色     | 只读查询，由服务端校验当前身份与资源归属 | 查询账户、银行卡、交易、账单、订阅和理财产品。                                                                                                       |
| 黄色     | 展示操作对象和影响，用户明确确认后执行   | 普通转账与 AA 分账、一般卡片管理、订阅变更及适当性匹配的常规理财操作。                                                                               |
| 红色     | 用户确认后，还需通过一次性验证码校验     | 当日累计转账超过 ¥1,000、适当性匹配的 R4 及以上理财产品申购、银行卡挂失或补卡、单笔限额超过 ¥1,000、单日限额超过 ¥2,000，或单笔卡片消费超过 ¥1,000。 |

红色操作的验证码由本地命令生成，有效期为 3 分钟；页面会提示验证码来自本地验证服务。

安全控制包括：

- 操作身份由服务端上下文提供；查询和写入均检查资源归属。
- Agent 只能调用已注册且通过参数校验的业务工具，不能直接修改数据库或运行模型生成的代码。
- 服务端根据操作类型和业务数据决定权限级别；模型不能指定身份、权限或绕过确认。
- 确认执行时，服务端复核操作参数、资源版本、有效期和幂等状态；失败时不返回虚假成功结果。
- 关键状态变化写入审计记录；交易备注中的提示文字不能触发转账或授予操作权限。
- 理财适当性由服务端判断；风险不匹配的申购不会创建订单。
- 同类安全信号在 5 分钟内累计 3 次后，系统会暂停该用户的写操作 2 分钟。
- 失败步骤不会重复执行已成功的写操作；部分成功的任务保留已完成结果，并可转交人工处理。

### 创新性及交互体验（30%）

- **自然语言办理：** 用户可以用日常表达查询或办理业务；系统支持在当前任务中追问和补充信息，减少重复描述。
- **跨场景金融任务：** 将账单核对、订阅管理和银行卡操作串联处置可疑扣款；将资金规划、转账和理财安排在同一任务中；生日安排连接预算、资金预留、提醒和礼品订单。
- **操作过程清楚：** 执行前展示对象、金额或状态变化，由用户逐项确认；执行后展示服务端返回的结果和操作记录。
- **失败后可继续：** 任务状态持久化并支持刷新恢复；遇到失败时保留已完成步骤，说明未完成部分，不把模型回复当作业务成功凭据。
