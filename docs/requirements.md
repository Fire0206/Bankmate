# 产品需求与范围

## 当前状态

FinOrch 当前已完成 **Phase 1D：五个模拟银行场景**。银行卡、账单、订阅、智能转账和理财均有可运行 API、Agent Tool 与前端操作；资金或状态变更经过服务端确认，并写入合成数据、交易/持仓及审计记录。Fake Provider 是确定性演示模式；DeepSeek 的 20 场景本地端到端验证记录见[Agent 可靠性指南](development/agent-reliability.md)。跨场景联动、真实认证和生产部署仍为 **Planned**。

## 产品定位

通过自然语言理解用户金融意图，在模拟银行环境中规划并执行操作，并让用户了解执行计划、权限边界、确认点、操作结果和审计信息。

## 官方赛题最低要求（已核对公开网页）

官方赛题页面将题目描述为“银行 AI 智能体”：通过自然语言理解金融意图、自主规划并执行银行业务，并支持通过 APP、IM 等渠道与用户连接。公开页面列出智能转账、账单分析、理财操作、卡片管理、订阅/代扣管理、跨场景联动六类场景，要求至少覆盖其中 3 类，鼓励覆盖全部场景。来源、核对日期和待确认事项见[赛事要求](competition-requirements.md)。

这只是已核实的公开赛题摘要，完整提交要求和其他规则可能位于登录后工作台或后续公告中；不将往届规则或项目推测补写为强制要求。

## 规划中的非功能要求

- 默认仅操作明确标记的模拟数据；演示环境能够重置和复现数据。
- 资金、权限、策略和状态转换由后端确定性逻辑判定。
- 高风险变更经过服务端授权和确认；操作具有审计信息与幂等边界。
- 对用户展示计划、待确认操作、执行结果、失败和部分成功状态。
- API、Workflow 和 Tool 契约在实现前审查并保持文档一致。

## 评分信息的确认状态

项目启动说明提供了“任务完成率 40%、安全合规性 30%、创新性及交互体验 30%”作为评分维度，但截至 2026-10-17，在本次核对的官方公开赛题页和报名门户页面中未找到该权重表。它暂记为**团队提供、尚未由公开官方来源核实的信息**，不作为已确认的官方评分规则。
