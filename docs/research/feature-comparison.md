# 六大场景与 Agent 能力对照

> 六大场景是 FinOrch 的项目目标与自选扩展规划。本轮无法从公开官方页面核实赛事强制场景、赛题最低要求或评分细则，不将其标为官方要求。源码证据按[各项目固定 commit](open-source-review.md)链接。

| **订阅与代扣管理** | SBI Dost 的[取消操作只修改 JS 内存状态并插入虚构交易](https://github.com/JatinGargz/sbi-dost/blob/61331ab73a3f2ff3c21961a9c4554523495757f4/src/mockAgent.js#L41-L55)。Airwallex 有账单和订阅类 mock，但状态仍是模拟 transport 内存。agentBANK 可通过账户和支付服务组合，但不是自动扣款运营时钟。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Subscription、Mandate、RecurringSchedule、Bill、PaymentAttempt；发现候选、暂停/恢复/取消 mandate、列账单。                                  | 仅模拟商户/扣款，不触发外部取消；服务端校验 mandate 所属用户与状态；有确认挑战、幂等和审计；展示下一期影响与数据来源。                                           | 续费提醒、扣款失败重试、用户可配置策略、账单预测。                         |
| **跨场景联动**     | BankPilot 将 ADK、BigQuery 和远程 MCP 组合，但平台重且依赖 GCP。Banko 的[收据→欺诈→预算图](https://github.com/cockroachlabs-field/banko-ai-assistant/blob/892ea2e59681304edb370147ee003d6e9752f7bf/banko_ai/agents/receipt_workflow.py#L164-L225) 验证有状态顺序图；并非六大零售银行业务完整联动。Airwallex 多个 kit 展示多步金融流程。                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | WorkflowTask、WorkflowStep、ToolExecution、Confirmation、AuditEvent；各业务工具共享一套任务协议。                                           | 至少一个跨域流程中可显示每步状态、确认、部分成功和失败；所有状态由服务端记录；执行顺序和副作用通过集成测试断言。                                                 | 可恢复的复杂分支、并行规划、长时等待、人工接管；达到需求再评估 LangGraph。 |

## Agent、工具和安全能力

| 能力           | 源码证据                                                                                                                                                                   | 评估与 FinOrch 做法                                                                                                      |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 受控工具选择   | agentBANK 用 domain routes/schema/service；Aegis 用动作 map 调用 fake HTTP 服务；BankPilot 用 ADK Tools/MCP                                                                | Adopt 概念：受控 registry + Pydantic 输入输出 schema。Agent 不直接调用数据库，也不让模型定义权限。                       |
| 风险判断与审批 | Kaching 服务端动作 whitelist、角色/PIN、proposal expiry 与 audit；Airwallex CLI gate 无 TTY 默认自动批准                                                                   | Adapt 安全边界；Reject 自动批准默认。FinOrch 的 challenge 和最终策略由服务端持久化校验。Kaching 代码许可不允许一般复用。 |
| Workflow 状态  | Banko 有持久化 LangGraph 收据图；SBI 的执行轨迹是固定前端步骤；Aegis trace 属 mock 执行结果                                                                                | 任务事件从服务端 Workflow 状态生成，前端仅订阅/轮询展示。不得将动画或模型思考文本冒充执行记录。                          |
| 重试与幂等     | Airwallex 在结果不明时按 request_id 查询；agentBANK 使用 fapiInteractionId 查重但查询在事务外；BankPilot 幂等字典仅在进程内                                                | 唯一幂等键和执行记录写在 SQLite；同 key 不同 payload 返回冲突；网络/数据库超时先按 key 查结果，不能盲重放。              |
| 持久化和复现   | RBC 本地 SQLite、agentBANK PostgreSQL、Banko CockroachDB、BankPilot BigQuery、SBI/Aegis/Airwallex mock memory                                                              | FinOrch 以 SQLite、可重置 seed、DB migration、持久化 task/audit 作为 Phase 1 起点；不复制其他项目的基础设施。            |
| 测试有效性     | Aegis fake tool tests；Airwallex idem/ledger tests；agentBANK smoke test 有 DB 才运行；Banko checkpoint/tool tests 需 DATABASE_URL；BankPilot 既有 stream 测试只验证有文本 | 所有写操作测试都检查最终数据库状态、唯一性、审计和失败路径，不以回答文本作为成功依据。                                   |
