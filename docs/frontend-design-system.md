# BankMate 前端设计规范

本文是正式产品界面的唯一视觉与样式维护入口。新页面优先复用现有组件和 tokens，不另建一套颜色、字体或布局规则。

## 样式入口

- `apps/web/src/main.tsx` 按路由加载样式。正式产品使用 `apps/web/src/styles/app.css`；`/showcase` 的历史样式只在该独立页面加载。
- `styles/tokens.css`：颜色、字体、字号、间距、圆角和焦点样式。
- `styles/base.css`：全局重置、正文和可访问性基础规则。
- `styles/layout.css`：导航、顶栏、主内容区和移动端布局。
- `styles/components.css`：按钮、表单、对话、确认、弹层、列表和状态。
- `styles/pages.css`：账户总览及各业务页的专属布局。

样式使用 `reset → tokens → base → layout → components → pages` 的 Cascade Layers 顺序。不要在页面组件中新增全局覆盖文件，也不要依赖 `!important` 调整层级。

## 视觉规则

- 颜色从 tokens 取值：白色页面、浅灰辅助面、深色文字和细分割线。成功、风险与失败可使用语义色，并同时配文字或图标。
- 中文和数字统一使用系统无衬线字体栈：macOS 优先 PingFang SC，Windows 优先 Microsoft YaHei UI，随后回退 Noto Sans SC 与系统无衬线字体。不下载字体文件。
- 正文使用 15–16px；次级信息不低于 13px。金额使用等宽数字特性并右对齐。
- 以字号、字重、留白和对齐组织内容。列表优先使用轻分割线；只有确认、表单或必须聚焦的业务内容使用单层容器。
- 桌面与手机共用页面组件。手机采用单列与底部导航，交互控件至少 40px 高，保留安全区域空间。
- 只呈现 API 返回的业务数据。不得在页面中补造金额、状态、账户、卡号或统计趋势。

## 交互与内容

- 业务操作结果必须来自服务端；写操作保留服务端确认、OTP、取消、幂等和审计链路。
- 错误、部分成功、待确认和等待补充信息要分别表达，不能用动画或本地状态伪装完成。
- 默认隐藏工具名、任务编号和审计细节；用户需要处理的信息、操作对象和金额必须直接可见。
- 虚拟数据与外部模型说明集中放在账户说明中，不在每个页面重复提示。
- 保留 `/showcase` 独立布局。除非任务明确涉及该页面，不要修改其中组件或历史样式。

## 核心页面构图

- 账户总览先展示可用余额；本月收入、支出与账户数量放在同一资金区域。下方以交易记录为主列、待核对事项为侧列。没有足够且可比较的月份数据时，不绘制趋势图。
- 交易行只使用 API 中的商户、类别、时间、金额和核对状态，不使用虚构商户图标。选择交易后展示其实际详情与服务端账单提示依据。
- 银行卡页只突出当前选中的卡和对应操作；其他卡作为轻量切换行列出。卡面比例保持银行卡横向比例，卡号只展示 API 提供的尾号。
- 冻结、解冻、挂失、线上支付与限额变更继续通过助手和服务端确认流程提交。前端不得直接改卡状态或先行显示成功。
- 视觉焦点限于每个页面的一处主要区域。默认用字号、字重和间距组织信息；额外卡片只用于确需单独确认或突出金融对象的内容。

## 修改后的检查

在 `apps/web` 下运行：

```sh
pnpm lint
pnpm typecheck
pnpm build
pnpm test:results
```

涉及接口类型时，同时在仓库根目录运行 `pnpm api:types`，并检查生成类型差异。界面修改需检查桌面与窄屏布局、键盘焦点、待确认、失败和空数据状态。
