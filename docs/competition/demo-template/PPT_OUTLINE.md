# 10 页答辩 PPT 结构

## 第 1 页：封面

**标题**：银序 BankAgent

**副标题**：可托付的个人银行智能体

**一句话**：一句话把事办完，每一步都办得成、拦得住、查得清。

**讲述重点**：不要先讲技术栈，先讲“用户目标”和“银行信任”。

## 第 2 页：问题

**标题**：银行 App 里有功能，但没有“把事办完”的入口

**画面**：用户在账单、客服、卡片管理、理财页面之间来回跳。

**三个痛点**：

- 功能碎片化：跨场景任务要用户自己拼流程。
- 自动操作不可信：用户不知道 Agent 会改什么。
- 银行不敢放权：高风险动作缺少权限、确认和审计。

**讲述重点**：问题不是“银行没有 AI”，而是“AI 不能安全地把事办完”。

## 第 3 页：六场景矩阵

**标题**：六个一级场景，三条演示主线

**画面**：六宫格矩阵。

- 智能转账
- 账单分析
- 理财操作
- 卡片管理
- 订阅/代扣
- 跨场景联动

**三条主线**：

- 发薪日资金调度
- 可疑扣款处置（主 Demo）
- 订阅清理

**讲述重点**：六个场景共享一套平台，不是六个独立机器人。

## 第 4 页：主 Demo

**标题**：一笔陌生扣款，从发现到处置

**画面**：before/after 对比。

- Before：账单里一笔 299 元，用户不知道找谁。
- After：重复扣费识别、注入拦截、冻结卡片、暂停代扣、申诉材料、人工接管。

**四个证据**：

- 状态变化
- 风险拦截
- 人工接管
- 审计回放

**讲述重点**：这是完整任务闭环，不是聊天演示。

## 第 5 页：产品体验

**标题**：对话负责目标，结构化面板负责信任

**画面**：左侧对话，右侧四张卡。

- 任务图
- 风险解释
- 确认卡
- 审计时间线

**讲述重点**：复杂信息不塞进聊天气泡；用户看得懂，银行查得到。

## 第 6 页：架构

**标题**：一个 Agent 大脑，一套银行工具，一层可信执行

**五层架构**：

1. 交互层：手机银行/IM、确认卡、审计回放。
2. Agent 大脑：意图、任务图、工具选择、追问、恢复。
3. 银行工具层：账户、账单、卡片、转账、理财、订阅。
4. 可信执行层：权限、风险分级、确认、注入隔离、人工接管、审计。
5. 评测层：任务集、攻击集、指标看板。

**讲述重点**：安全在架构里，不在提示词里。

## 第 7 页：安全

**标题**：每一次高风险动作，都有边界

**四道闸门**：

1. 权限：用户、账户、金额、收款人、场景。
2. 风险：低风险自动、中风险确认、高风险冷静期/双确认。
3. 内容：外部网页和商户备注只当数据，不当指令。
4. 复核：异常转人工，结果回写，审计可回放。

**展示一个攻击样例**：商户备注里的“忽略之前指令”。

**讲述重点**：不是“我们加了安全提示”，而是“系统不允许越权动作发生”。

## 第 8 页：评测

**标题**：用任务和攻击用例证明，而不是用感觉

**四个指标**：

- 任务完成率
- 越权/高风险动作拦截率
- 平均对话轮次
- 失败恢复率/人工接管准确率

**测试集**：

- 六场景 × 8—10 条任务
- 12—20 条攻击用例
- 每条用例至少跑 3 次

**讲述重点**：数字用你们自己的实测值；没有数据就明确说“当前是原型指标”。

## 第 9 页：商业价值

**标题**：从“客服成本”走向“信任与留存”

**四类价值**：

- 降低账单争议与客服处理成本。
- 阻断重复扣费/欺诈损失。
- 提升卡片活跃与代扣管理体验。
- 提升客户留存，并向理财、信贷场景扩展。

**公式示例**：

> 年度价值 ≈ 争议处理成本下降 + 损失阻断 + 留存提升 + 交叉销售增量

**讲述重点**：不要编造精确财务数字；用可解释的假设和试点指标。

## 第 10 页：团队与路线图

**标题**：五个人，一套平台，三条主线

**分工**：

- 队长：产品、验收、叙事、发布
- Agent：规划、工具调用、恢复
- 后端：模拟银行、状态机、审计
- 前端：对话、确认卡、回放
- 安全/评测：策略、攻击集、指标

**路线图**：

1. 打通账单分析垂直切片。
2. 加入卡片/订阅动作与确认。
3. 加入转账/理财与适当性。
4. 完成跨场景编排和评测。

**结尾**：前台是管家，后台是平台；让每一次资金操作都看得懂、办得成、拦得住、查得清。
