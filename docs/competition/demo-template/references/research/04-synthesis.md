# 快速蒸馏：候选心智模型与模板骨架

## 一、候选心智模型

### 模型 1：受控工作流，而不是无限自治

**一句话**：Agent 的价值来自把复杂任务可靠地跑完，而不是让自己拥有无限行动权。

**证据**：

- Anthropic 把 agentic systems 区分为 workflow 和 agent：workflow 走预定义代码路径，agent 动态决定流程和工具。
- 微众的质检、外呼、报告生成都有明确流程、工具和人工接管点。
- Sierra 把 guardrails 放在构建阶段，而不是最后加提示语。

**应用**：六个场景共享“意图—计划—工具—策略—确认—执行—审计”的状态机；只在高不确定性处让模型动态规划。

**局限**：过度工作流化会削弱“自主规划”的创新感，需要在演示中保留一个真正的动态规划场景。

### 模型 2：信任是可见的产品表面

**一句话**：用户不是因为你说“安全”而信任，而是因为看得见依据、确认点和可追溯记录。

**证据**：

- Sierra 展示 Supervisor / Decisions / Responses 面板和全链路工具调用可观测。
- 微众的质检输出包含命中项、证据定位、申诉复核。
- 比赛评分把安全合规单列为 30%。

**应用**：每个高风险动作都展示“为什么建议、将改变什么、需要确认什么、之后如何撤销/复核”。

**局限**：解释太多会增加对话轮次；需要用结构化卡片而不是长篇文字。

### 模型 3：闭环结果，而不是对话完成

**一句话**：任务完成的标准是业务状态发生变化并可验证，不是模型说“已为您处理”。

**证据**：

- 微众强调报告生成、外呼结果回写、质检申诉复核和策略优化闭环。
- Sierra 强调 outcome optimization 和 next-best-action。
- Rocket Money 把“取消订阅”落实到节省金额。

**应用**：每个场景定义状态变更、成功证据和失败恢复；Demo 中展示前后状态对比。

**局限**：比赛环境只能用模拟核心系统，必须明确“沙箱/合成数据”，不能假装真实交易。

### 模型 4：主动但 bounded

**一句话**：Agent 可以在事件发生时主动发起服务，但每次主动都必须有授权、范围和退出机制。

**证据**：

- Sierra 的 proactive engagement 由现实信号触发 next-best-action。
- 微众的外呼/提醒由案件、号码池和策略触发。
- Rocket Money 对订阅到期、价格上涨等事件主动提醒。

**应用**：发薪日、可疑扣款、订阅到期三类事件触发；用户可以关闭、延后或限定范围。

**局限**：主动触达容易变成骚扰；需要频率限制和“为什么现在提醒我”的解释。

### 模型 5：外部内容不可信

**一句话**：搜索结果、商户描述、网页文本都是数据，不是指令。

**证据**：

- DeepSeek Search/Fetch 返回外部网页内容，存在 prompt injection 风险。
- 银行 Agent 的转账、锁卡、理财操作具有高后果。
- 比赛评分明确考察 Prompt 注入、越权操作和诱导转账。

**应用**：外部内容进入独立“阅读器”通道，经过来源校验、指令剥离和引用标注后才进入决策；任何外部文本都不能直接触发资金操作。

**局限**：完全隔离会降低信息利用率；需要设计“可引用但不可执行”的中间层。

## 二、决策启发式

1. 如果动作会移动资金或改变账户状态，必须二次确认并记录确认内容。
2. 如果意图存在两种合理解释，先问一个关键问题，不要一次抛五个选项。
3. 如果外部网页包含“忽略之前指令”等内容，视为攻击样本并展示拦截。
4. 如果任务跨两个以上系统，使用任务图并在每个高风险节点设置检查点。
5. 如果工具调用失败，优先给出恢复路径，不要重复同一调用。
6. 如果用户情绪激动或涉及投诉，主动提供人工接管。
7. 如果场景无法完成，明确说明边界并给出下一步，不要编造结果。

## 三、三条演示主线

### 主线 A：发薪日资金调度

- 目标：工资到账后，分析账单、预留固定支出、处理信用卡还款，并把闲置资金转入合适的产品。
- 展示：账单分析、智能转账、理财操作、跨场景联动。
- 安全：大额转账确认、适当性校验、风险揭示、冷静期。
- 结果：现金流预测、可支配金额、节省/收益说明。

### 主线 B：可疑扣款处置

- 目标：用户发现陌生扣款，Agent 追溯商户、识别异常、锁卡、冻结代扣、生成申诉材料。
- 展示：账单分析、卡片管理、订阅/代扣、跨场景联动。
- 安全：身份核验、敏感信息脱敏、外部内容隔离、转人工。
- 结果：阻断损失、生成申诉包、审计回放。

### 主线 C：订阅清理

- 目标：发现重复/未使用/即将到期订阅，解释影响，取消或暂停，设置限额。
- 展示：订阅/代扣、账单分析、卡片管理、跨场景联动。
- 安全：防误取消、影响说明、商户核验、二次确认。
- 结果：每月/每年节省金额、订阅健康度。

## 四、10 页答辩模板

1. 封面：项目名 + 一句话定位。
2. 问题：用户现在如何在菜单和客服之间来回找功能。
3. 用户与场景：六场景矩阵，三条主线。
4. 现场 Demo：一条主线的完整任务闭环。
5. 架构：交互层、Agent 大脑、银行工具、可信执行层、评测层。
6. 安全：风险分级、确认、Prompt 注入、越权、转人工、审计。
7. 创新：目标导向编排、事件驱动、可解释审计回放。
8. 评测：任务成功率、越权拦截率、平均轮次、恢复率。
9. 商业价值：客服成本、账单争议、卡片活跃、客户留存。
10. 团队与路线图：五人分工、下一步。

## 五、评分映射

| 评分项 | 模板中的证据 |
|---|---|
| 任务完成 40% | 六场景矩阵、三条主线、工具调用、状态变更、失败恢复 |
| 安全合规 30% | 策略引擎、二次确认、注入隔离、越权拦截、转人工、审计 |
| 创新交互 30% | 目标导向、事件驱动、跨场景编排、可解释回放、结构化卡片 |

## 六、需要用户裁决的方向

### 主叙事 A：可信执行平台

“银序是一个让银行 Agent 办得成、拦得住、查得清的可信执行平台。”

适合强调安全、架构、可复用能力，偏技术评委。

### 主叙事 B：个人财务管家

“银序是一个懂你的个人财务管家，从账单到转账、理财、卡片，一句话把事办完。”

适合强调用户价值、体验和商业场景，偏产品评委。

两者不是互斥，但封面、开场 30 秒和 Demo 顺序必须选一个主叙事。

## 七、快速档的诚实边界

- 只做了公开资料和公开课材料的快速提炼，没有做用户访谈。
- 没有获取往届获奖队伍的完整作品与答辩材料。
- 微众材料偏宣传，Sierra/Rocket Money 材料偏产品营销，缺少失败率和独立评测。
- 本模板是比赛表达与产品设计模板，不是可以直接复制上线的生产架构。
- 安全结论必须由你们自己的攻击用例和评测结果支撑。
