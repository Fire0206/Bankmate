# Demo 线框图说明

## 画面目标

用一张桌面端工作台同时回答两个问题：

1. 用户是否觉得这是一个“懂我的财务管家”？
2. 评委是否看得出这是一个“可信执行平台”？

## 五个评审点

1. **左侧对话**：用户只说目标，不需要自己找菜单。
2. **风险卡**：外部商户备注里的注入内容被隔离，只当证据，不当指令。
3. **确认卡**：展示操作对象、影响范围、可逆性和二次确认。
4. **右侧任务图**：展示 Agent 的多步骤执行链和当前进度。
5. **审计回放**：所有动作可追溯，人工接管有上下文。

## 界面分区

- 左侧导航：对话、账单、卡片、订阅、理财、审计。
- 顶部：案件状态、合成数据标识、人工复核状态、可信执行状态。
- 主对话区：用户目标 → 追问 → 调查 → 风险提示 → 确认 → 执行 → 转人工。
- 可信执行面板：任务图、风险摘要、证据、审计入口。

## 当前交互状态

画面展示的是“用户已确认、操作已执行、申诉材料生成中、案件转人工复核”的状态。

所以确认卡里同时保留了：

- 两个动作的勾选状态；
- “已确认”标签；
- “已确认执行”按钮；
- 执行后的绿色状态卡。

这不是“待确认”静态页，而是整个主 Demo 的关键一帧。

## 需要团队评审的三个设计问题

1. 右侧“可信执行面板”是否一直显示？
   - 对评委展示很好；
   - 对普通用户可能信息过载。
   - 备选：默认收起为“为什么这么做”，演示时展开。

2. 二次确认用卡片还是弹窗？
   - 卡片适合连续对话和审计回放；
   - 弹窗更适合高风险操作的强制打断。
   - 备选：高风险用弹窗，中风险用卡片。

3. 手机端如何折叠？
   - 对话优先；
   - 任务图和审计放到“案件详情”页；
   - 确认卡必须全屏展示，不能压缩成一行。

## 下一版可以补的画面

- “待确认”状态：用户还没点确认时的按钮和风险提示。
- “注入拦截”特写：商户原文、隔离原因、策略命中。
- “人工接管”详情：交接上下文、处理时限、客户无需重复描述。
- “审计回放”抽屉：按时间轴展开 9 个事件。
